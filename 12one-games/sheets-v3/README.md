# 12one Games — Google Sheets edition (development)

**Status:** Functional development candidate, not production-approved. The legacy and Supabase pages are unchanged. Never test with real participant data until a disposable workbook and browser tests pass.

## Install

1. Create a new private Google Sheet (not the existing Supabase or legacy workbook). Keep sharing restricted to trusted workbook owners. In Extensions > Apps Script, replace the contents of Code.gs with the entire `12one-games/sheets-v3/Code.gs` file in this branch.
2. In Project Settings > Script properties, add `INITIAL_ADMIN_PASSWORD` with a unique 14–128 character password (a long randomly generated password is preferred). Do not put the password in source, a URL, or GitHub.
3. In the Apps Script editor save the project, select `initializeWorkbook` from the function dropdown, then Run. Authorize access to the spreadsheet and script. If prompted, select your account and review permissions. The function creates `_ADMIN`, stores `WORKBOOK_ID`, a random `AUTH_PEPPER`, and a salted keyed admin credential, and deletes INITIAL_ADMIN_PASSWORD on successful setup. If a failed setup leaves the initial password property, correct the issue and rerun. Do not rotate the pepper; doing so invalidates credentials and sessions. Initialization does not overwrite existing game data.
4. Use Deploy > New deployment > Web app. Description: 12one Games Sheets v3. Execute as: Me (the workbook owner). Who has access: Anyone (anonymous access, if allowed by your Google account or organization). Deploy and copy the URL ending in /exec. If Anyone is not offered, this anonymous client cannot work for all players under that account.
5. Test `/exec` in a private browser window: it should return a small JSON health response rather than a sign-in screen. The public endpoint intentionally returns no private data on GET.
6. In `12one-games/sheets-v3/config.js`, set endpoint to the full /exec URL. This URL is not a credential. Do not set the /dev testing URL. Until the branch is merged, GitHub Pages normally serves main, not this branch; preview the branch by downloading it and serving locally via HTTPS or localhost, or by a separately authorized preview deployment. Keep config and deployment decisions on the development branch until approved.
7. Open admin3.html in the preview. Sign in using the initial admin password. Generate a one-credit invitation, copy it immediately, and open host3.html in a separate browser profile. Create an account, redeem the invitation, create a test game, and copy its player link. Open the appropriate player page from a separate browser profile.
8. Register at least three test players using fictional display names and individual PINs. For Mafia assign roles or use Start game. For Assassins enable actions or use Start game. Verify gameplay, dashboard and registration controls, permissions, and the workbook layout. Test desktop and mobile including iOS Safari. Do not merge or announce a release before the checklist passes.

## Transport and browser compatibility

The four pages contain the actual frontend and call the Apps Script web app using HTTPS POST with `text/plain;charset=UTF-8` (simple request, no custom authorization header or cookies), JSON body, and redirects followed. Apps Script ContentService may redirect to script.googleusercontent.com; the browser must permit CORS on the complete redirect/response path. No credentials are placed in URLs; no JSONP, no no-cors opaque response, and no launcher redirection. **Live cross-origin behavior has not been verified and is a deployment blocker.** If it fails, check deployment visibility and the browser console first. Do not make the Sheet public or disable authentication to work around CORS. An HTML Service bridge with explicit origin checks may be required in a future commit; it is not implemented here.

## Workbook layout

_ADMIN: A:F hosts; H:O invitations; Q:X registry; Z:AD sessions; AF:AG platform settings; AI:AJ game-type defaults (JSON); AL:AO audit. Per game: A:N player fields; P:Q settings; S:T round state; V:AA events; AC:AE idempotency receipts. Two frozen header rows, named sections, separate game sheets. Default Sheet1 is retained untouched. Boolean settings use actual Sheets TRUE/FALSE values, numeric settings use numbers, and text settings use text. Manually edit only supported setting value cells with the correct type while gameplay is paused and no requests are running. Never edit IDs, sessions, hashes, player roles/targets, registry, or audit cells manually. Default JSON settings should be edited from the admin UI. Changing a gameplay toggle directly in Sheets does not initialize a new round; use the host UI for activation.

Phone/hall are off by default; use fictional display names for test games, minimize personal information, keep the workbook private, and use the game as an entirely digital, opt-in activity. No physical pursuit or contact is required. Public Assassins feed is deliberately anonymized: it never reveals real names or private codenames. The host audit retains the involved player IDs. Public winner text is also anonymized. Private player dashboards display only game-relevant identity data.

## Recovery, update, backup

- Host can change password; admin can set a replacement password in the directory (share privately, then have host change it). Host sessions are revoked. Do not email reusable passwords in plain text.
- To recover admin access, create `RECOVERY_ADMIN_PASSWORD` in Script Properties, run `recoverAdministrator` from the editor, and authorize if needed. It changes the credential, removes the property, and invalidates administrator sessions.
- To update backend, copy the reviewed new source into Apps Script, save, then Deploy > Manage deployments > Edit > New version > Deploy. Keep the existing /exec URL if possible. Preview against a separate workbook first.
- Backup: File > Make a copy of the private workbook; also retain the Apps Script source and securely preserve AUTH_PEPPER and ADMIN_CREDENTIAL separately. A workbook copy alone is not a complete credential backup. Do not commit secrets or data. Export each game from its Activity tab for a credential-free JSON record.
- Deletion retains an internal tombstone so consumed credits cannot reappear, and removes only the matching game sheet. Export before deleting.
- If you see a timeout, refresh and inspect whether the action succeeded. Repeated create and play requests with the same request ID are deduplicated; other actions may not be. If a sheet is created but the registry update fails, or a registry deletion succeeds but the sheet removal fails, stop and reconcile manually using backups; cross-sheet operations are not atomic. Never delete unrelated sheets.
- Errors: incorrect URL or sign-in HTML => deployment visibility; 403 => account access restrictions; failed fetch => CORS/network; busy => retry after a short wait; invalid credentials => verify account and PIN; quota errors => reduce concurrent requests.
- Free Apps Script has execution, simultaneous execution, and daily quota limits. The current adapter uses a script-wide lock and batch reads/writes; it is not designed for unlimited simultaneous games. There is manual refresh rather than continuous polling. Load test and measure latency before larger events. See https://developers.google.com/apps-script/guides/services/quotas and https://developers.google.com/apps-script/guides/content.

## Security and test status

Tokens are hashed server-side and expire after one day for host/admin, seven days for players; saved browser sessions are optional. Credential hashes use a unique salt and server-only HMAC pepper; this is not a memory-hard password KDF. Rate limiting currently uses CacheService, which is best-effort and may evict entries, not a durable brute-force defense. Stronger credential hardening, persistent/global rate limiting, session storage review, transaction recovery, live concurrency and load verification remain release blockers. Never expose the workbook to players. All protected game actions check server-side roles/ownership and two-step confirmation proofs are time-bound. Client DOM output is text-based, and sheet text is escaped to prevent formulas. Review on a real workbook.

Run locally: `node 12one-games/sheets-v3/tests.cjs` and `node 12one-games/sheets-v3/transport.test.cjs`. Tests execute the production backend core against a fake data store, a mocked Sheets range adapter, and mocked fetch transport, not Google services. See PARITY.md and TEST-RESULTS.md. The frontend is implemented but requires full browser integration tests. Do not treat this as a production-ready release.
